Learn the framework

The workshop's framework has three parts: an ability profile, an adaptation, and a way to verify it. You can try each one on Redbird.

Ability profile

A profile says what a person needs, in their own words. The toolkit keeps it in the person's account, and every app and adapter they use reads the same one. For example, Dario's profile asks for plain language and less motion, so the store rewrites hard paragraphs for him and holds moving things still.

The person edits their profile in the extension's Profile tab or on the console's Profiles page. Adapters and apps say which needs they meet, and the toolkit suggests them to the people whose profiles could use them. A profile is a starting point the person changes, not a description of them. The four shoppers on Redbird are made-up examples of what different profiles turn on.

Adaptation

An adaptation changes the page to remove a barrier the person runs into. There are two kinds:

  • An adapter is one small file of code that changes one thing on a web page, and puts the page back when it's turned off. It runs in the person's own Chrome, through the extension, on the pages it was made for. The toolkit has 11 built in, like text-size and calm-page, and you build new ones.
  • An app's own adaptation is built into the app itself. Redbird is an app like that: real-arrival-dates and calm-urgency are part of the store. It follows the person's toolkit profile, and shows up under Apps in the developer console, where the person (or a coding agent) can turn its adaptations on and off.

Both are built on the toolkit's building blocks: small, tested pieces for things like styles, announcements, keyboard shortcuts and AI text. Every change goes through a session, so turning an adaptation off puts back exactly what it changed.

Verification

Verification is how you, and the person, can tell a change did what it should and didn't break anything else. With the toolkit it happens in three layers:

  • Checks while you build. Each preview in the extension's Builder runs checks: whether the adapter ran, which accessibility problems it added or fixed, and whether the page jumped around. The assistant can only offer an adapter whose checks passed.
  • A review in the background. After the first version is built, the toolkit checks it again on copies of the page and has reviewers look at what it changed, while you keep trying it. On Redbird, the red and green badges and the Audit tab show which problems are fixed too.
  • Testing with people. Use the page the way the person would, for example with a screen reader, with only the keyboard, or zoomed in to 200%. Only the person can tell you whether it works for them.
