Learn the framework

The workshop's framework has three parts: an ability profile, an adaptation, and a way to verify it. You can try each one on Redbird.

Ability profile

A profile says what a person needs, in their own words. The toolkit reads it to decide what to change. For example, Dario's profile asks for short, plain sentences, so the reading-level adapter rewrites hard paragraphs for him.

The idea is for each person to make their own profile. On Redbird, pick My profile in the panel's Profiles tab and answer a few questions, and the toolkit writes your profile and picks adapters for it. You can save it as a file for the toolkit's browser extension, so it works on other websites too. The four shoppers in the Profiles tab are made-up examples of what different profiles do.

A profile also remembers your changes: if you turn one of its adapters off, it stays off next time. When you build, describe the person you're building for in the Build your adapter tab, under Who is it for?.

Adaptation

An adaptation changes the page to fix the accessibility problems that person runs into. The toolkit has two kinds:

  • An adapter is code that changes one thing on a page, and turning it off puts the page back. The toolkit has about 40. For example, motion-reducer stops animations.
  • A skill has no code. It lists a few adapters to turn on together for one need, in a short file called SKILL.md. For example, the toolkit's calm-browsing skill turns on motion-reducer, dark-mode and focus-mode.

The panel's Build your adapter tab can make both, the same way the toolkit's browser extension does. It first looks for adapters the toolkit already has, and writes them up as a skill. If none of them fit, AI writes a new adapter.

Verification

Verification is how you, and the person, can tell a change did what it should and didn't break anything else. On Redbird you can check it three ways:

  • In Profiles, open each adapter's list of changes to see them before and after, and turn on Show accessibility problems on the page at the top of the panel to see which ones are fixed.
  • In Audit, run the audit. It counts common problems, like photos with no description. After you press Fix this page, run it again and the count goes down.
  • Use the page the way the person would, e.g., with a screen reader, with only the keyboard, or zoomed in to 200%.
