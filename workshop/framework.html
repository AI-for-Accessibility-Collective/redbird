Profile, adaptation, verification

The workshop's framework has three parts: the ability profile, the adaptation and the verification. Each one is part of the toolkit, and you'll use all three when you build on Redbird.

Ability profile

An ability profile says what a person needs, in their own words and as settings. The toolkit reads it to decide what to change. For example, Dario's profile sets his reading level to grade 6, and the reading-level adapter rewrites any paragraph harder than that.

  • In the toolkit, profiles are JSON files. See the workshop's three, sam.json (opens in a new tab), mark.json (opens in a new tab) and dario.json (opens in a new tab), and the toolkit's own in tools/profiles/settings.json (opens in a new tab).
  • On Redbird, the Shop as menu in the Setup tab picks a profile. When you build, write your own in the Build tab's Who are you building for? box, in a sentence or two from your card game. Both builders read it.

Adaptation

An adaptation is a change to the page for that person. The toolkit has two kinds:

  • Adapters are code. Each one fixes one kind of problem, and switching it off puts the page back the way it was. The toolkit has about 50. For example, motion-reducer stops animations, and skip-links adds "Skip to main content" for keyboard users.
  • Skills are recipes, with no code. A skill names a few adapters for one need, in a short file called SKILL.md. For example, the toolkit's calm-browsing (opens in a new tab) skill turns on motion-reducer, dark-mode and focus-mode.

The toolkit's Chrome extension has a builder for each. In the Skill Builder, an AI model the toolkit calls the Engineer picks adapters for a need you describe. In the Adapter Builder, AI writes a new adapter from your description. The Build tab on Redbird has both, and it gives the AI the same instructions the extension does.

Verification

Verification is how you, and the person, can tell that a change did what it should and didn't break anything else. On Redbird you can check this in three ways:

  • The Changes tab lists every change, before and after, and what a screen reader hears.
  • The Checks tab runs the toolkit's auditors and axe-core, the same checks the extension runs before it fixes a page. Run them before and after you turn on a fix, and compare the counts.
  • Use the page the way the person would, e.g., with a screen reader, with only the keyboard, or zoomed in to 200%.

When an AI agent shops for the person, verification also means checking the agent's work. The toolkit's verification layer does this in the Chrome extension. It stops the agent and asks the person first whenever the agent is about to do something the person didn't ask for, like keeping a protection plan that was already ticked. See Where an agent should stop.
