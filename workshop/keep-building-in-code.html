Build it in code

If someone on your team can run a coding agent (e.g., Claude Code, Codex or opencode), you can build a fix in code, with the toolkit's skill, for as many rounds as it takes.

The Builder in the extension is the quickest way to a first version. In code, you can read every line, keep the file in your own folder, and ask the agent for exactly the change you want. The skill gives the agent the same steps the Builder follows: ask what the person needs first, build on the toolkit's building blocks, publish it to your account, run it in your browser, and check it.

Get ready

  1. Do the setup, so the extension is connected to your team's account.
  2. Get the toolkit's folder on your computer: download the toolkit (opens in a new tab) and unzip it, or clone its repository (opens in a new tab). It has the skill in .claude/skills/ai4a11y-toolkit. You need Node.js (opens in a new tab) 18 or newer.
  3. In the developer console, open Adapters and press + New adapter. It shows two lines, the toolkit's address and your team's token. Save them in a file called .env at the top of the toolkit folder. It looks like this:
    Text
    TOOLKIT_URL=https://toolkit-service-774429076434.us-central1.run.app
TOOLKIT_TOKEN=aat_…
  4. Open the toolkit folder in your coding agent.

Note

The token lets anyone act as your team on the toolkit. Keep it in .env, and don't paste it into the chat or share it.

Ask for the fix

Tell the agent who the fix is for, what gets in their way, and where. For example:

Text
Build an adapter for the Redbird store at https://redbird-workshop.vercel.app/*. Sam is blind and shops with VoiceOver. On the search results, each rating is a picture of stars, so VoiceOver only reads the number of ratings. Read the star ratings out as numbers, like 4.6 out of 5 stars.

The agent picks up the toolkit's skill. It asks you a few questions first, like who the change helps most. Then it writes the adapter, publishes it to your account, and the extension runs it on the store within a few seconds, without reloading the page.

Some helper commands the agent runs, which you can run too, from the toolkit folder:

  • node .claude/skills/ai4a11y-toolkit/scripts/adapter.mjs check checks that the toolkit sees your browser.
  • node .claude/skills/ai4a11y-toolkit/scripts/adapter.mjs status <id> says whether the adapter ran on the pages you opened, or what went wrong.
  • node .claude/skills/ai4a11y-toolkit/scripts/adapter.mjs verify <id> runs the toolkit's checks and a review, and says what to fix.

Who does what

If someone on your team has the access need you're designing for, they should be the one testing each version. If not, one person on the team uses the store with the same tools the person would use (e.g., VoiceOver or only the keyboard).

  • The tester uses the store with their own tools (e.g., their screen reader) and says what's wrong, without needing to read any code.
  • The coder asks the agent for changes, and reads its answers out loud if the tester can't see the screen.

Each round

  1. The tester tries the page the way they would, and finds what's still wrong.
  2. The coder tells the agent, in the tester's own words, for example "VoiceOver reads the rating twice" or "Tab never reaches Add to cart".
  3. The agent changes the adapter and publishes it again. The page runs the new version by itself.

Tip

Ask the agent for one change at a time. Each publish is a new version, so you can ask it to go back to an earlier one.

Test it

After it publishes, the agent runs the toolkit's checks with verify. They say whether the adapter ran, which accessibility problems it fixed or added, whether turning it off puts the page back, and what reviewers found when they looked at its changes. The review can take about 10 minutes.

These checks don't know what your tester needs (e.g., whether they can Tab to Add to cart). Give the agent each check from your verification plan, like "VoiceOver reads each price as one number", and ask it to check that too.

Share it

Ask the agent to share it, or run node .claude/skills/ai4a11y-toolkit/scripts/adapter.mjs share <id>. Then see Test it and share it.
